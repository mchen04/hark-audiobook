# Repository anatomy

Last reviewed: 2026-08-13

This note explains why a raw line count approaches 140,000 and which large
paths are authored code, required generated state, or disposable local output.

## Tracked-line breakdown

The August 2026 audit counted 140,319 lines across 417 tracked files:

| Path or file                     |  Lines | Classification                                              |
| -------------------------------- | -----: | ----------------------------------------------------------- |
| `drizzle/`                       | 58,702 | required SQL history and generated snapshots                |
| `src/`                           | 46,335 | application plus co-located unit tests                      |
| `tests/`                         | 18,488 | browser, parity, sync, resume, and performance verification |
| `pnpm-lock.yaml`                 |  8,460 | required generated dependency state                         |
| `public/`                        |  4,375 | authored service worker, pinned model/PDF assets, icons     |
| `scripts/`                       |  1,492 | build and test tooling                                      |
| `docs/`                          |  1,455 | maintained product and operations docs                      |
| `LICENSE`, `README.md`, root, CI |  1,012 | license, entry documentation, config, workflows, patches    |

The number is therefore not 140k lines of production application logic.
Required generated state — Drizzle's cumulative snapshot chain plus the
lockfile — accounts for 67,162 lines, just under half the repository. Of
`src/`, 17,124 lines are co-located unit tests, which leaves roughly 29,200
lines of application code. Test infrastructure across `src/` and `tests/`
totals about 35,600 lines.

Reproduce the table with the script in [Counting consistently](#counting-consistently);
do not hand-edit these figures.

## Generated but required

`drizzle/meta/*.json` is not disposable build output. Drizzle Kit reads the
snapshot chain, validates parent/version relationships, and compares the
current schema with the latest migration state when generating the next SQL
migration. Removing old snapshots breaks that history. Drizzle's own
[`generate` documentation](https://orm.drizzle.team/docs/drizzle-kit-generate)
describes the SQL-plus-snapshot output.

`pnpm-lock.yaml` pins exact dependency resolution and is required for
reproducible frozen installs.

Both paths are marked `linguist-generated` in `.gitattributes`. GitHub documents
that attribute as the way to collapse generated files in diffs and remove them
from repository language statistics:
<https://docs.github.com/en/repositories/working-with-files/managing-files/customizing-how-changed-files-appear-on-github>.

## Large authored files

These files are large, but they are referenced and behavior-bearing:

- `tests/resume/harness/resume-oracle.ts` (5,185 lines) is the shared
  cross-process/device resume oracle used by three Playwright suites. It is not
  bundled into production. Its size is maintainability debt and a candidate for
  decomposition, not evidence that it should be deleted.
- `src/lib/playback-core.ts` (1,738 lines) is the pure playback decision core —
  chapter selection, smart rewind, start-position resolution, and per-user local
  device state. `playback-core.test.ts` (1,642 lines) is its unit oracle.
- `src/lib/offline-sync.test.ts` (1,590 lines) covers the outbox boundary:
  coalescing, idempotent replay, and conflict reconciliation.
- `src/lib/offline/idb-migrate.test.ts` (1,408 lines) carries every shipped
  IndexedDB schema forward and proves that downloads, transcripts, queued
  writes, and deletion state survive.
- `src/app/styles/player.css` (1,329 lines) is authored player UI, not compiled
  CSS.
- `tests/perf/launch-benchmark.spec.ts` (1,142 lines) owns the launch oracle.
- `public/sw.js` is maintained directly and is the shipping service worker; it
  is not generated by the build.

`public/models/kestrel/*.onnx` are pinned binary model graphs. `wc -l` reports a
line count for them because they contain incidental newline bytes; that number
measures nothing. They are content-addressed by SHA-256 in
`src/lib/kestrel/asset-manifest.json` and reproduced byte-for-byte by
`pnpm verify:kestrel-export`.

This audit does not disguise authored files as generated to improve statistics.
Future structural work should split a large file only along real ownership
boundaries and preserve each oracle's ability to fail.

## Disposable local output

The following remain ignored and should never be committed:

- `.next/`, `out/`, `tsconfig.tsbuildinfo`, and `next-env.d.ts`;
- `node_modules/`;
- `test-results/`, `playwright-report/`, and `coverage/`;
- `.data/`, uploads, local mail captures, and imported book files;
- `.env*` except the checked-in examples;
- `.vercel/`, editor state, and agent scratch directories.

Test MP3s under `tests/fixtures/` are exceptions: tests reference these small
files directly. `public/icon-source.svg` is the retained source asset for the
generated PNG icons.

## Counting consistently

For repository size, count tracked files rather than the working directory. This
regenerates the breakdown table above:

```sh
git ls-files | xargs wc -l | sort -rn | head -20   # largest tracked files
git ls-files | xargs wc -l | tail -1               # total tracked lines
git ls-files 'src/**/*.test.ts' 'src/**/*.test.tsx' | xargs wc -l | tail -1
```

A working-directory count includes dependencies and compiled Next.js output and
can be hundreds of megabytes larger. GitHub's language panel is byte-based and
honors `.gitattributes`; it is not the same metric as source lines.
